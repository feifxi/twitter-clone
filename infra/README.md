# Infrastructure

Everything that runs the app in AWS, as code. Local development only needs the root
[`docker-compose.yml`](../docker-compose.yml).

| Folder | What |
|---|---|
| `terraform/bootstrap` | Created once, kept: Route 53 name servers and the GitHub Actions deploy role (free) |
| `terraform/app` | The stack: VPC, EC2 host, ECR, S3 media + CloudFront, SSM config, DNS zone, alarms, budget |
| `compose/` | What runs on the host: the compose file, Caddyfile and deploy script ([README](compose/README.md)) |
| `observability/` | Prometheus rules, Alertmanager, Loki, Alloy, the Grafana dashboard ([README](observability/README.md)) |
| `scripts/` | `up.sh`, `deploy.sh`, `down.sh` |

## AWS overview

Region `ap-southeast-1`, domain `twitter.chanombude.me` (a subdomain delegated to Route 53; the
main domain stays where it is). The stack exists only while you need it: `up` → use it → `down`.

One `t4g.medium` (arm64) runs Caddy, the web app, the API, Postgres and the monitoring stack in
Docker Compose. Media lives in S3 behind CloudFront. Nothing else runs: no RDS, NAT or load balancer.

Cost while up: about **$1.3 a day** (on-demand list prices: mostly the instance, plus its public
IP and disk). After `down`, close to $0; each up also creates a Route 53 zone ($0.50 for any month
it exists more than 12 hours). An AWS Budget emails you at 50% of `monthly_budget_usd` ($20).

Terraform state is local and git-ignored. The app stack's state holds the generated passwords, so
keep it private, and don't delete it while the stack is up (Terraform would lose track of it).

## One-time setup

You need an AWS account, a domain you control, the AWS CLI (`aws configure sso` or an access key)
with the [Session Manager plugin](https://docs.aws.amazon.com/systems-manager/latest/userguide/session-manager-working-with-install-plugin.html),
Terraform and Docker.

1. **Bootstrap** (name servers and the deploy role):
   ```bash
   cd infra/terraform/bootstrap && terraform init && terraform apply
   terraform output name_servers
   ```
   If the account already has GitHub's OIDC provider (another project created it), add
   `-var create_github_oidc_provider=false`.
2. **DNS:** at your DNS provider, add four **NS** records for the host `twitter` (one per name
   server above). Check with `dig +short NS twitter.chanombude.me` once the stack is up.
3. **Settings:**
   ```bash
   cp infra/terraform/app/terraform.tfvars.example infra/terraform/app/terraform.tfvars
   ```
   Fill in the delegation set ID (`terraform output delegation_set_id` in bootstrap), your email and
   the Google client ID; optionally the Gemini key and a Discord webhook for alerts. Every secret
   (database password, token key, Grafana password) is generated by Terraform.
4. **Google sign-in:** add `https://twitter.chanombude.me` to the OAuth client's authorized
   JavaScript origins.
5. **Continuous deployment (optional):** add the repository **variable** `AWS_DEPLOY_ROLE_ARN`
   (Settings → Secrets and variables → Actions → Variables) =
   `terraform -chdir=infra/terraform/bootstrap output -raw github_deploy_role_arn`. It isn't a secret.

## Using it

```bash
infra/scripts/up.sh       # terraform apply (shows the plan, asks first), then deploy (~5 min)
infra/scripts/deploy.sh   # code changes only: build, push, deploy over SSM, check the site
infra/scripts/down.sh     # terraform destroy (asks first); the data goes with it
```

After `up`:

- Site `https://twitter.chanombude.me`, Grafana `https://grafana.twitter.chanombude.me` (user
  `admin`, password: `terraform -chdir=infra/terraform/app output -raw grafana_password`).
- Certificates appear within a minute or two once DNS resolves.
- Confirm the "AWS Notification - Subscription Confirmation" email to get alarm emails.

## Deploys

`deploy.sh` runs the same way from your machine and in CI. It reads everything it needs from the
`/chmtwt/deploy/config` SSM parameter the stack writes, so it needs no Terraform state.

1. Builds both images for arm64, tagged with the commit SHA (`-dirty-<time>` for uncommitted
   changes), and pushes them to ECR. Tags are immutable; an image that's already there is skipped.
2. Uploads that commit's `infra/compose` and `infra/observability` to `s3://<bucket>/stack/<sha>/`.
3. Runs `twitter-deploy <sha>` on the host over SSM Run Command. It syncs the stack files, and
   [`compose/deploy.sh`](compose/deploy.sh) renders the env files from SSM Parameter Store, starts
   the stack, waits for every health check and reloads the configs. If the release isn't healthy
   within 3 minutes, the host redeploys the previous one and the deploy fails.
4. Checks `https://<domain>/readyz` and the home page.

**CI/CD:** every push to `main` runs the checks, then the deploy job runs `deploy.sh --skip-if-down`
on an arm64 runner. When the stack is down it does nothing, so CI stays green. The job trades
GitHub's OIDC token for the bootstrap role, which can only push this project's images, upload its
releases and run commands on its instance (no AWS keys in GitHub). Redeploy by hand: Actions →
CI/CD → Run workflow.

**Roll back:** `infra/scripts/deploy.sh <earlier-sha>` redeploys that release exactly as it was.

## On the host

Shell access goes through Session Manager (no SSH port, no keys):

```bash
aws ssm start-session --target $(terraform -chdir=infra/terraform/app output -raw instance_id)

sudo -i
cd /opt/twitter/stack/compose
dc() { docker compose -f compose.prod.yaml --env-file /opt/twitter/state/stack.env "$@"; }
dc ps
dc logs -f api web caddy
dc exec postgres psql -U twitter                # the database
tail -f /var/log/cloud-init-output.log           # first-boot progress
```

## Checks

CI runs these on every push (no AWS account needed):

```bash
cd infra
terraform fmt -check -recursive
terraform -chdir=terraform/app init -backend=false && terraform -chdir=terraform/app validate
terraform -chdir=terraform/app test             # plans the stack against a mocked AWS provider
terraform -chdir=terraform/app plan             # against your account (read-only)
```

## Security notes

- Only Caddy's ports (80, 443) are open. Shell and deploys go through SSM; IMDSv2 only.
- Postgres, Prometheus, Loki and Alertmanager are only reachable inside the compose network;
  Grafana is behind Caddy with a generated admin password and no sign-up.
- Secrets are generated by Terraform, stored as SSM SecureStrings and written to `0600` env files
  on the host at deploy time. They are never in user data, git or workflow logs (they are in the
  local state file: keep it private).
- The disk is encrypted; ECR scans images on push; the media bucket is private (CloudFront reads it
  with Origin Access Control).
